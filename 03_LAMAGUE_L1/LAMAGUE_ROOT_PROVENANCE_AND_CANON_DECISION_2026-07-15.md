## 4. Canon decisions

### Decision C-01 - LAMAGUE is the formal core

**CANON:** LAMAGUE is the typed symbolic grammar for encoding states, transformations, invariants, fields and compression/governance operations.

It is the machine-oriented and formally parseable layer.

### Decision C-02 - LAMAHGUE is a separate layer, not a spelling variant

**CANON:** LAMAHGUE is the metric-executable / performative language layer that binds expressions to AURA constraints, scores and human-readable constitutional acts.

The root documents show it predates the clear LAMAGUE formalization, but the mature architecture should place it above LAMAGUE rather than merge the names.

### Decision C-03 - GEOMATRIA remains the spatial layer

**CANON:** GEOMATRIA encodes spatial and geometric relations. It is not part of the minimal LAMAGUE grammar.

### Decision C-04 - Treat LAMAGUE as a proper name

The corpus contains multiple incompatible acronym expansions. Until Mac deliberately chooses one, **LAMAGUE should be canonically treated as a proper name**, with historical expansions recorded in `HISTORY/NAMES.md`.

This prevents accidental canon drift through retrospective backronyms.

### Decision C-05 - The root class system is four classes

The canonical kernel begins with:

```text
I - invariant
D - dynamic
F - field
M - meta
```

Later connection, time, resource and grounding classes should be registered as extensions or subtypes until a formal type-system migration is completed.

### Decision C-06 - Separate operator and state meanings

The corpus overloads `Ψ` as drift field, awareness state, fold/correction operator and memory integration.

That ambiguity must be repaired before parser canon. Proposed distinction:

```text
Ψ      epistemic/drift state field
Fold() correction/integration operation
Ψ_inv  invariant or stabilized state
```

A distinct glyph may later replace `Fold()`, but the parser must not assign one token incompatible types.

### Decision C-07 - Unicode codepoints are constitutional data

The root PDFs visibly substitute or corrupt some glyphs. The symbol registry must store:

- rendered glyph;
- Unicode codepoint sequence;
- ASCII alias;
- canonical name;
- class and type signature;
- historical variants.

No symbol should be canonized from appearance alone.

## 5. Reference implementation audit

### Verified

- Python syntax compilation: **PASS**.
- TRIAD example: **RUNS** and converges in the tested seeded run.
- Multi-agent example: **RUNS** and produces high alignment with the declared anchor in the tested seeded run.

### Self-found defect

The supplied full example suite stops during Pyramid Cascade:

```text
AssertionError: Cascade increased entropy:
0.052631523545764676 -> 0.07660122056595578
```

This is a valuable constitutional failure: the implementation enforces its own claim and catches the violation rather than silently reporting success.

**Cause class:** the current compression/demotion operation does not guarantee that the chosen entropy functional decreases. The new foundation block itself can have greater measured evidence variance than the old foundation.

**Required repair:** either:

1. change the cascade transformation so it mathematically guarantees non-increasing total entropy under the chosen functional; or
2. redefine the invariant to the quantity actually intended (for example normalized layer entropy, contradiction load, or uncertainty per retained evidence); or
3. weaken the claim and log an obligation rather than assert monotonic decrease.

### Implementation status

**Register:** PROTOTYPE / PARTIALLY EXECUTABLE.

It is stronger than pseudocode, but not yet a production reference implementation because the main example suite does not complete and no automated tests, parser, serialized symbol registry or reproducible benchmark harness were supplied in this root batch.
