# SXP-L — proposed next research gate, not a feature promise

v2.0 should not just be a name. Suggested requirements:

1. **Third-party comprehension pilot**, preregistered: at least one participant wholly unfamiliar with the language; compare new viewpoint markers vs the fully named form; record comprehension errors and completion time. A genuine publishable result requires a larger, planned sample and controls.
2. **A larger compositional core**: conditional clauses, negation, questions, quotations and tense should preserve binding in every supported nesting pattern, or be rejected for explicit reasons.
3. **Operational semantics**: separate roles for speaker/holder/addressee/reporter and distinguish proposed from asserted statements in an independently specified AST.
4. **Phonological confusion study**: test roots spoken by different accents, with recordings and blind listening, not text edit-distance alone.
5. **Translation loss accounting**: compare English, JSON, canonical SXP-L, short SXP-L, and speech; report each representational loss with a recoverability route.
6. **Independent code audit**: investigate identity forgery, untrusted inputs, CSV injection, speculative interpretation, and denial-of-service bounds before any wider integration.

Keep the scope human-first and make permission boundaries independent of language claims.
