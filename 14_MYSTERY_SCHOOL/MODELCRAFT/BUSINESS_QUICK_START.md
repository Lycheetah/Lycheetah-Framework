# What eats your time every week?

Choose one task and map it before buying or automating anything.
This worksheet can be completed on paper with no model service.

| Field | Write down |
|---|---|
| Task | One repeated job in ordinary language |
| Current effort | Approximate hours per week and how you estimated them |
| Inputs | Where they come from; who has permission to use them |
| Output | What a useful completed result looks like |
| Risk if wrong | The concrete cost of an error |
| Human approval | Who decides before sending, charging, deleting or changing a record |
| Budget | Zero, a specific limit and currency, or unknown |
| Measurement | Time, errors, rework and whether the result actually helped |

## Choose the smallest useful route

**Do not automate:** the task is rare, the permission is missing, a simpler rule
works, or there is no acceptable way to handle a consequential error.

**AI assist:** let a person review a draft, summary or classification while keeping
responsibility for the result. First try the workflow with invented examples.

**Bounded automation:** use a narrow repeatable operation with explicit authority,
known failure behavior and a reversible result. Define its limit before connecting tools.

**Agent candidate:** consider a multi-step tool workflow only after the simple
prototype demonstrates a need. This worksheet grants no access or execution authority.

For quote requests, a draft-only first version could be:

```text
Read a permissioned example → identify missing information → prepare a draft
→ human reviews → human decides whether to send
```

Try [Outcome First and Context Pack](FIRST_EXPERIMENT.md), then record baseline
effort, draft quality and review burden. Include setup and checking time in any
before/after claim. A smaller burden is a hypothesis until measured; no savings
estimate is generated by this packet. Keep customer data private and minimize it.
