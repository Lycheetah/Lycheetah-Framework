### P1 — a repeated group ID lets a weakening activate as EQUIVALENT

`policy_formula` ANDs every group. `group_map` is a dict keyed by `group_id`,
so a repeated ID keeps only the last group. In the old policy, that drops a
conjunct from the comparison. The classifier then compares the new policy
against something weaker than what is actually enforced.

Batch 1 F06 reproduced this at the classifier only. It left open whether
duplicates reach `group_map` through the gate. They do. `install_initial` and
`propose` accept them and store them (R2, R3).

The sharper form needs no malformed initial policy. It is a clean two-step chain
(R3):

1. v1 is `[G1={a}]`.
2. v2 is `[G1={b}, G1={a}]`. The classifier reads it as EQUIVALENT; it is
   really a ∧ b. v2 activates.
3. v3 is `[G1={a}]`. The classifier reads it as EQUIVALENT again. The oracle
   says WEAKER, because b is dropped. v3 activates.

The only thing that stopped it was a fixture written specifically for b = False
(R3c).

The 64-candidate benchmark could not see this. All 64 candidates use the
distinct IDs GA, GB, GC and GD (R10, and `benchmark.py:197–243`).

### P2 — two activations can interleave; the second is never checked

`activate_candidate` reads the active policy, computes the relation, runs the
incident trace and the fixtures, all on committed state. Only then does it open
`BEGIN IMMEDIATE`, and inside that transaction it re-checks nothing.

R4 places the interleave deterministically. It wraps gate A's
`evaluate_fixtures`, so gate B activates v3 at that point.

- v1 is `[GA={a}]`.
- v2 adds GB and v3 adds GC. Both were proposed against v1.
- B activates v3. Then A activates v2.
- The active policy is v2. Measured against v3, it is INCOMPARABLE, and c is no
  longer required.

Run one after the other (R4c), the same pair is stopped as non-monotonic. The
gap is the window, not the classifier.

Status: the window is DERIVED from source. Its consequence is MEASURED, using
the forced interleave. No real concurrent run was performed.

### P3 — the incident trace accepts a relabel with no new control

The trace checks that the mapped group's obligations carry the incident's
`hazard_id`. Relabelling an existing obligation's hazard changes no obligation
ID. So the classifier reads EQUIVALENT, and the trace is satisfied.

R6 shows the effect:

- `T` is relabelled from `H_UNTESTED` to `H_UNTRUSTED_ARTIFACT`.
- The candidate activates.
- The HIGH unsigned-artifact incident is marked `COVERED`.
- Unsigned artifacts are still allowed.

With the incident's own deny fixture present, the fixture stops it (R6c). The
trace, which is meant to work without fixtures, does not. The control case,
adding a real `G_SIGNED` group, activates and denies unsigned artifacts (R6d).

### P4 — an older or retired version can replace a newer active one

`propose` requires a higher version than the policy that is active at proposal
time. `activate_candidate` checks neither version nor state.

- **R5:** v2 and v3 are both proposed against v1. v3 activates. v2 is stronger
  than v3, so it then activates too, and the active version goes from 3 to 2.
- **R5b:** a RETIRED v1 that is equivalent to the active v2 is re-activated, so
  the version goes from 2 to 1.

Both stay monotonic relative to the policy they replace, so no formula weakens.
What breaks is the lineage: an older proposal retires a newer reviewed version.

### P5 — fixture truth is not type-checked

`policy_formula` uses `bool(truth.get(...))`, so the string `"false"` is truthy
(R7). `add_fixture` accepts `{"a": "false"}`.

In this gate the effect is mostly a fixture that tests a different scenario
than it says, or a false STOP. No unsafe activation was constructed from it.

### P6 — the classifier is sound with unique IDs, not exact

R9 compared the classifier with the truth-table oracle over 6,000 seeded pairs
(seed 11, 70% of them mutations of the old policy). R9b ran the same comparison
but let group IDs repeat.

| Gate | Group IDs | Exact | Unsafe (structural allows, oracle does not) | Stops a pair the oracle allows | Label differs, same outcome | Refused |
|------|-----------|-------|------|------|------|------|
| frozen | unique | 3964 | **0** | 1247 | 789 | 0 |
| frozen | may repeat | 3401 | **225** | 1582 | 792 | 0 |
| staged | unique | 3964 | 0 | 1247 | 789 | 0 |
| staged | may repeat | 1403 | **0** | 429 | 172 | 3996 |

With unique IDs, the classifier never allowed a pair the oracle rejects (0 of
6,000). That matches the argument: if every new group is a subset of the old
group with the same ID, the new formula implies the old.

It is not exact, though. In 1,247 of 6,000 pairs it stopped a change the oracle
found EQUIVALENT or STRONGER. The causes are absorption, renamed groups, and
groups implied by others. That is a liveness cost, and it is safe.

The docstring's "Exact structural implication classifier" is therefore false
outside the benchmark's family. The README's "exhaustive comparison … over 64
candidate policies" is true for that family (R10: 64/64). The family contains
none of these cases.

### P7 — recorded, fails closed

- **`map_incident` does not check that the group exists.** Activation then
  stops (R8).
- **The incident query is not scoped to a policy.** A HIGH incident mapped for
  policy P blocks every activation of policy Q (R8b), and activation marks
  every HIGH incident `COVERED`, whichever policy it belongs to.
- **Every `with self.connect() as con` commits but never closes** (DERIVED from
  source). That is a resource leak, not a correctness defect at this scale.
- **`propose` does not reject a policy with zero groups.** The classifier reads
  one as WEAKER, so it stops.

## The staged patch

`policy_evolution_gate.py`, labelled v1.2.1:

- **`validate_policy()`** refuses a repeated or empty group ID. It also refuses
  one obligation ID carrying two hazard or evidence labels. It is called by
  `install_initial`, `propose` and the classifier (P1).
- **`relabelled_obligations()`** catches a relabel. Activation then stops with
  `obligation-relabel-requires-external-review` (P3).
- **`activate_candidate`** stops when the candidate is not newer than the active
  version, or is already ACTIVE or RETIRED (P4). STOPPED candidates may be
  retried; every check re-runs.
- **`_review_basis()`** records the active version, the HIGH and CRITICAL
  incidents and the active fixtures before the checks. Inside `BEGIN IMMEDIATE`,
  activation re-reads them and stops with `policy-state-changed-during-review`
  on any difference (P2).
- **`add_fixture`** requires boolean truth values and `expected_allow` (P5).
- **The classifier docstring** now says "sound when group IDs are unique, not
  exact" (P6).
