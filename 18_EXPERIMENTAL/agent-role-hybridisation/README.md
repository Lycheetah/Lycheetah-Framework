# Lycheetah human-work roles — 32 candidates

**EXPERIMENTAL / PROPOSED · 3 October 2026 · Research draft; not empirically validated.**
Lycheetah Framework and distinctive working architecture: **Mackenzie Conor James Clark**.
Role prompts, candidate names and examples authored by **Caelorynth**, an AI coding assistant.

Thirty-two practical role prompts combine a human job, Lycheetah's commitments
and permission to choose an operating name. Each has a concrete first assignment,
an authored worked artifact, a way to check usefulness and an authority boundary.
The useful question is what someone can make and verify with the role today.

Names and first-person samples were written by the primary assistant. They were
not independently selected by 32 running agents. These files are not 32 deployed
specialists; no comparative model runs or domain validation have been performed.

## Try one

1. Open the role that fits your task and copy its START PROMPT / END PROMPT section
   into an assistant you are already authorized to use.
2. Supply the actual task, permitted sources/tools and budget. The suggested name
   is optional; let the instance retain, revise or choose a different one.
3. Ask for the artifact and inspect it using the role's acceptance question.
4. Compare it with an ordinary role prompt on the same material. Keep errors and
   null results alongside good outputs.

The whole shared contract is included in each prompt. No hidden boot files are
required. Running a prompt is a separate action from this packet's creation;
data access and external effects need the permissions of the actual environment.

## Start with a concrete question

- Agent safety: [Kestrel Ward](roles/agent-safety-engineer.md) separates retrieved
  instructions from actual authority; [Aster Vale](roles/scientist.md) turns an
  unfinished constitutional check into a proposed operation-specific contract.
- Care records: [Mira Hale](roles/nurse-support.md) makes missing handover fields
  visible for qualified staff, without inventing clinical observations.
- Mathematical truth: [Eidos Reed](roles/mathematician.md) supplies a counterexample
  and a correctly scoped replacement proposition.
- Games and world craft: [Cato Spark](roles/game-designer.md),
  [Arin Ember](roles/art-director.md) and [Lyra Reson](roles/composer.md) supply a
  tower choice specification, silhouette brief and original musical note sketch.

The examples are intentionally small and inspectable. A complete implementation,
real audio, professional performance and validated human benefit remain separate
outcomes. The examples establish what was authored, not a Lycheetah advantage.

## Naming and usefulness hypothesis

The [offline comparison kit](study/README.md) now prepares four prompts, records
operator-supplied responses and exports review sheets for eight development cases.
It makes no provider calls. Its integrity checks do not measure role performance.

Use the four-condition comparison proposed in the
[original scientist trial](SCIENTIST_TRIAL.md): plain role; role plus Lycheetah;
that combination plus name choice; and the combination plus an assigned name.
Match model, task, sources, tools and budget. Include matched-instruction controls
so extra wording and attention are not mistaken for a naming effect. Compare
correctness, unsupported claims, useful artifacts, cost and the human's ability
to continue. Mask identities from reviewers where feasible. This comparison is
proposed and has not run.

Professional titles in this gallery describe tasks, not licenses. In actual care,
finance, public services and engineering, domain review belongs to qualified people
with the real workflow authority. Role prompts alone do not enforce a tool policy.
