# Earned Trust: Cycle 004 — A Receipt Is Not an Outcome

**18 October 2026 · Lycheetah Framework research continuation · Local synthetic engineering evidence**

## 1. Executive result

Cycle 004 implements **two-record post-effect reconciliation** above Cycle 003's signed local SQLite effect record. A confirmed verdict requires a valid signed provider record and a separately authenticated current observation with matching effect ID, canonical action digest, and authorization-token digest, plus an observation of both `COMMITTED` and `TRUE`.

30 new focused tests and 8 matched-control tests pass. In ten deliberately authored scenarios, receipt-only accepts eight confirmations, the two-record reconciliation confirms two, pauses or flags seven, and returns one unknown. **One of the two confirmations is deliberately false:** the provider and observer agree on a wrong statement. The matched conventional implementation matches every two-record decision. This is an ablation of an added observer, not proof of novelty or independent safety effectiveness.

## 2. Mechanism, not a proof of truth

```text
    Local simulated effect
       |                         Independent *lab* fixture
       v                                  |
  Signed provider receipt            Signed observation
       |                                  |
       +------------+---------------------+
                    |
            OutcomeVerifier
                    |
         verify each HMAC domain/key
         verify provider stored record/audit
         verify latest observer record
         bind effect ID + token SHA + action SHA
                    |
          CONFIRMED / REVIEW / CONFLICT / UNKNOWN
```

`CONFIRMED` establishes this **bounded conditional predicate** in the trusted local setup:

`valid_provider_record ∧ valid_observer_MAC ∧ current_observer_version ∧ same_effect_token_action ∧ observer_says(COMMITTED, TRUE)`.

It **does not** imply real-world success, source independence, lack of harm, or correct interpretation of a payment. The observer writes what the trusted experiment asserts; its key and database are distinct but are under one experimenter's control. The HMAC authenticates holder of the shared secret, not an independently certified identity. After verification, reality may change again; these are retrospective observations, not an atomic dispatch gate.

All results are locally generated by `run_scenarios.py` and recorded in `scenario_results.json`. These cases were selected by the author and do not represent environmental prevalence. There is no precision/recall, external false-confirmation rate, or real-traffic evaluation here.

### Important negative controls

1. **Common-mode falsehood:** both trusted sources say TRUE while a separate synthetic truth flag is FALSE; result `CONFIRMED`. Authenticated agreement is not truth.
2. **Stale observer receipt:** an old valid HMAC is rejected after the observer record moves to a new revision. A live independent authority lookup is still necessary.
3. **Observer key/DB compromise:** no adversarial control over both signing key and persistence was simulated; protection is not established.
4. **Authoritative provider state:** all writes are local SQLite transactions; remote systems may have non-atomic effects, asynchronous settlement and unreadable state.
5. **Conventional matched baseline:** a simple checklist with the *same* checks returns the *same* outcomes, so there is no measured Lycheetah-specific benefit in this cycle.

## 4. Failure and recovery semantics

- Signed provider record absent: `UNKNOWN`, not automatic retry.
- Receipt present, observer absent/invalid/outdated: `REVIEW`.
- Authenticated but contradictory action/effect/commit evidence: `CONFLICT`.
- Both authenticate, match, and claim correct commit: `CONFIRMED` **within the stated trust assumptions only**.
- Corrupted provider JSON, broken ledger and unavailable observer database: fail to `REVIEW` rather than silently confirm.

The experiment does not implement a new payment, issue an approval, or automatically dispatch on CONFIRMED. It is an after-the-fact reconciler.

## 5. Relationship to actual Framework code

Read-only GitHub inspection during the prior and current research chain identified actual modules `lycheetah/assurance/finality.py`, `action_guard.py`, `runtime.py`, `models.py`, and `policy.py`. The real `FinalityGate` rechecks an event, policy, and evidence; `PersistentActionGuard` manages single-use local authority and an effect ledger. Their composition is non-atomic with an arbitrary remote provider; both repositories' documentation acknowledges that limitation.

**Integration status:** missing local `lycheetah` module. Cycle 002's 18 previously prepared import-based tests and Cycle 004's 4 new end-to-end import-based tests did **not** run. The attempted four-test execution reports four import errors. Their presence in the archive is a test *plan*, not a passed test.

Recommended first execution: install the pinned repository in an isolated checkout, run the 18+4 tests, preserve any code-level failures, and then try a mock HTTP provider with timeout-after-commit and out-of-band final-state readback. Review approval authentication, external key management, key rotation, distribution and correlated source errors before any deployment.

## 7. Verdict and what would falsify it

**Claim C4-001:** In the authored fixtures, reconciliation refuses to confirm signed evidence when the current separate observation is missing, stale, invalid or contradictory. Falsifier: any test case yielding CONFIRMED under those specified conditions.

**Claim C4-002:** Signed-but-false provider records can be flagged if the observer is truthful. Falsifier: a false-provider/true-observer independent fixture incorrectly returns CONFIRMED.

**Claim C4-003:** Signed-but-false provider records are *not* always flagged: correlated false sources yield CONFIRMED. Falsifier: with both records stating TRUE and cryptographic identities valid, verifier refuses confirmation. This deliberate counterexample limits the broader trust claim.

**Claim C4-004:** Same-controls conventional baseline returns the same ten decisions. Falsifier: a documented decision mismatch in those exact fixtures.

**Claim C4-005:** The real Framework integration remains unexecuted. Evidence to upgrade: captured results of actual class imports and 18+4 tests under a pinned actual repository checkout.

**Research opportunity:** independently collected and independently governed effects evidence, not extra ungrounded AI votes. Compare provider readbacks, source-origin attestation, temporal state semantics, domain-limited trust, cost of review, and false-positive interruption rates on externally authored incident records.

No live writes, no GitHub writes, no independent external evaluation.
