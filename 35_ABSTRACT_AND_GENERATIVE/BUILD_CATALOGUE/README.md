# Lycheetah Build Catalogue

**Owner and Framework origin:** Mackenzie Conor James Clark. Product translation and briefs drafted with Caelorynth, an AI coding assistant, at Mac’s invitation. 4 October 2026.

**Status: PROPOSED catalogue.** This is one home for the tool, game and interaction ideas from the Framework scan. It is a source-linked possibility set, not thirty-one active projects, a product release, a scientific validation or a new portfolio campaign.

The question for each generation is practical: **what can a person do with it, and what visible result survives the session?** Lycheetah’s language can give the work atmosphere. Its mechanisms must give the person something to use, play, inspect or change.

The preceding inventory counted 2,358 files, including historical material and generated exports. That is an inventory snapshot, not a count of original contributions or working products. This collection preserves the twenty-six first concepts, four crossovers and an additional public recovery experiment as thirty-one build briefs. It remains open to better ideas beyond this list.

## How to bring one to life

Choose one ID. Resolve its source and current evidence. Put executable code in the existing product owner’s repository, with a link back to its card. Build the first complete interaction, observe it on the intended device, and save a receipt. Then revise its status with the actual commit, test result and known limits. Never make a prototype look finished by changing only the catalogue label.

No provider call, account creation, autonomous outreach, live execution or game rewrite follows from a catalogue entry. Local prototypes can begin with manual inputs and deterministic simulation. A later requested implementation batch supplies its concrete scope and permissions. Another collaborator, including AURA, can propose additions through the same template; this document does not claim those proposals have been requested or received.
