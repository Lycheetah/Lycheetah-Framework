# Add a generation

**Status: PROPOSED template.** Assign the next unused stable ID; preserve existing IDs.

## ID · Name

- **Form:** tool, game, interaction or crossover.
- **Promise:** one action a person can perform and one result they receive.
- **Source:** exact public files, creator attribution and source evidence status.
- **Mechanism:** what is reused, what is newly authored and what the source cannot support.
- **Inputs:** required information, units, privacy and uncertain values.
- **Interaction:** entry → choice → state change → feedback → return.
- **Artifact:** what survives the session and how to export or delete it.
- **First build:** one complete slice, intended device and existing owner/repository.
- **Acceptance:** observable success, meaningful negative case and baseline comparison where needed.
- **Limits:** unsupported claims, prerequisites and unresolved evidence.
- **Build receipt:** empty until observed; then commit, commands, results, device witness and failures.
- **Decision:** proposer, Mac’s actual decision if supplied, and next scope. A proposal is not permission for external effects.

Add the card to an appropriate part, update REGISTRY.json and link the implementation once it exists. Do not overwrite the source’s status with the prototype’s success. Another collaborator can submit this exact form without editing sibling constitutions or declaring itself the product owner.
