# ABSTRACT AND GENERATIVE REGISTER

This register tracks the epistemic and creative status of objects in this folder.

It is intentionally separate from the Framework's empirical claims register.

## Two-axis status

Each object should carry two independent descriptions.

**Epistemic status** asks: what may we claim is true?

Examples: observed, implemented, testable, conjecture, symbolic, worldbuilding, unknown.

**Generative status** asks: what does this object reliably create?

Examples: new questions, designs, stories, experiments, vocabulary, reflection, interfaces, research programmes, or cultural forms.

A high generative value never upgrades epistemic status.

A weak or falsified literal claim does not automatically erase generative value.

## Promotion rule

An Abstract and Generative object may enter empirical research only when a new version states:

- operational definition;
- measurable variables;
- controls;
- falsifier;
- provenance;
- nearest conventional baseline;
- what information is held equal;
- what outcome would count as no distinct advantage.

The generative ancestor remains preserved.

## Demotion rule

If an empirical interpretation fails, return the object to the strongest surviving register rather than deleting its lineage.

Examples:

- physical law fails -> analogy may survive;
- universal psychology fails -> personal or narrative model may survive;
- branded mechanism ties a generic baseline -> information structure may survive;
- metaphysical reading lacks evidence -> symbolic reading may survive.

This is not protection from criticism.

It is protection from category error.

## Non-convergence rule

Not every object requires one canonical interpretation.

When several readings are compatible with the evidence and serve different legitimate purposes, preserve them explicitly.

The branch may therefore contain scientific, personal, symbolic, fictional, and philosophical readings of the same originating object so long as their authority is not silently exchanged.

This is Polyphonic CASCADE applied to the repository itself.

## Attribution rule

Co-created objects should say so.

Where an idea emerged from human-AI dialogue, preserve:

- the human contribution when recoverable;
- the model or system involved when recoverable;
- date or session lineage when recoverable;
- whether the present formulation is recovered, revised, or newly synthesized.

Do not manufacture sole authorship after the fact.

## Final test

Before deleting, flattening, or "professionalizing" an object, ask:

**What capability would the corpus lose if this strange form disappeared?**

If the answer is non-trivial, preserve it and clarify its register instead.
