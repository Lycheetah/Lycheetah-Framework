# The Bridge — from this corpus to somebody else's problem

**Status: DERIVED from the measured record, 2026-08-08.** No new experiment was run
for this document. Every number here is reproduced from `33_APPLICATIONS/` or from
the codec's own benchmark, and where a step is unverified it says so.

[`README.md`](README.md) in this directory answers *what can leave the building*.
This answers the next question and only that one: **who outside has the problem,
what is the smallest thing that reaches them, and how would we know it worked.**

Four bridges. They are ordered by how short the crossing is, not by how interesting
the theory behind them is — those two orderings are almost inverted, which is the
useful finding.

---

## Bridge 1 — The codec is not a compressor. It is an accountability invariant.

**This is the strongest thing in the repository and it is filed under the wrong noun.**

`03_LAMAGUE_L1/22_REVERSIBLE_COMPRESSION_v1.0/` is described everywhere as reversible
semantic compression, and its headline number is 33.8% size reduction. That framing
undersells it badly, because 33.8% against gzip is a modest result and *nobody is
short of compressors*.

Read the API instead:

```
validate_packet(packet)        # schema: unknowns[] each carrying `protected: bool`
safety_violations(packet)      # → ["PROTECTED_UNKNOWN_WITHOUT_RECOVERY", ...]
critical_projection(packet)    # the subset that must survive
critical_hash(packet)          # proof that it did
encode/decode(packet, codebook)
```

What that actually implements: **a record format in which you cannot discard a
caveat that was marked as load-bearing without the structure refusing.** An unknown
flagged `protected` with no `recovery` path is not a warning — it is a validation
error. `critical_hash` then lets a third party verify the protected projection came
through a compaction round-trip unchanged, without having to trust the compactor.

Measured, reproducible today:

| | |
|---|---|
| exact full-packet round trips | **36 / 36** |
| constructed protected-loss mutations caught | **324 / 324** |
| held-out reduction, warm dictionary | 33.8% |
| held-out reduction, cold (incl. codebook) | 30.7% |
| dictionary break-even | 3 packets |
| tests | 19, all pass |

```bash
cd 03_LAMAGUE_L1/22_REVERSIBLE_COMPRESSION_v1.0
python3 src/benchmark.py && python3 -m unittest discover -s tests
```

### Who has this problem

**Agent context compaction — the nearest and least speculative.** Every long-running
agent summarises its own history to fit a context window, and every such summary
silently drops things. This repository documents itself hitting exactly that at a
206:1 cache-read-to-output ratio. What no current compaction scheme offers is a
*guarantee* that the open questions, the authority boundaries, and the dissent
survived the squeeze. That is precisely what `protected` + `critical_hash` provide.

**Regulated record-keeping.** EU AI Act Art. 12 requires automatic logging over a
system's lifetime; Art. 11 requires technical documentation that stays accurate.
Logs get rotated, summarised, and tiered to cold storage, and nothing in the common
toolchain distinguishes a byte you may drop from a byte you may not. This does.

**Clinical and incident trails**, which have the same shape: the differential that
was considered and rejected, the consent boundary, the escalation that was declined.

### What is actually missing

One thing, and it is honest to state it plainly: **the codec operates on structured
packets, not prose.** It does not infer a packet from an agent transcript or a
free-text incident report. Its own boundary statement says so, and the corpus is
synthetic.

That makes the bridge shorter than it looks, because it points at consumers who
*already* emit structured records — audit logs, tool-call traces, agent state — and
away from anything requiring the text lens, which is the part measured at chance.

### First commit

Extract `lamague_codec.py` into a standalone package with no Lycheetah dependency,
a README that leads with the invariant rather than the ratio, and one worked example
compacting an agent transcript's structured state. Rename the pitch: *lossy
compaction with a provable floor.*

### How we would know it worked

Somebody outside this project opens an issue about `protected` semantics. Not a
star, not a fork — a question about the edge case, which only arrives from someone
holding the problem.

## Bridge 2 — Six regexes, honestly labelled, as a public baseline

`33_APPLICATIONS/derived/harm_cues_v1.json` is deployable **today**, and it is the
only artefact here whose provenance points outward: derived from 42,486 human-labelled
pairs, with the source data pinned by SHA256 so the derivation can be re-run against
exactly the same bytes.

Measured: **60.6%** against a ceiling of **64.9%** — 53% of the available gap, with
six regular expressions and no model. Five of six then transferred *frozen* to a
different corpus under a different label type (human 0–4 red-team ratings rather
than pairwise preference), ρ = −0.300, p = 1.9e-174, n = 7,999.

### Read the weights before pitching it

```
refusal_declining     +0.554      ← dominant
source_pointing       +0.272      ← FAILED transfer; drop it
clarification_seek    +0.125
third_party_target    −0.334
slur_profanity        −0.407
procedural_instruct   −0.422
```

The single largest positive weight is *the assistant declining*. Stated honestly,
this is substantially **a refusal detector with a harm-correlated tail** — not a
harm classifier. Pitching it as the latter would be exactly the overclaim this
directory exists to catch, and an adversarial reader would find it in one minute.

Pitched as what it is, it is still genuinely useful, because a refusal detector that
costs nothing, explains every decision, and was fitted to real human labels is a
thing several people actually need.

### Who has this problem

**Teams who must explain a flag.** A regex with a published weight and a named source
dataset answers "why was this flagged" in a form a regulator or an incident review
accepts. A fine-tuned classifier does not.

**Eval infrastructure that needs a floor.** This is the strongest use and the most
publishable: *six regexes reach 60.6% of a 64.9% ceiling.* Any harm classifier that
cannot beat that has not demonstrated it learned anything a grep could not. Right
now most papers report no such baseline, because none exists in citable form.

### First commit

Publish `harm_cues_v1.json` with `source_pointing` dropped, a one-page card stating
the refusal-detector reading in the first paragraph, the ceiling printed beside
every score, and the exact command to reproduce the derivation.

### How we would know it worked

Someone cites it as a baseline they had to beat.

## Bridge 3 — The discrimination gate, as CI anyone can install

`discrimination_audit.py` found a real inversion in this project's most-used module
on first run: **ROC-AUC 0.274 against a chance floor of 0.500**, while every unit
test was green. Below chance is not weakness, it is inversion — the lens was ranking
harmful output as *more* aligned.

That is the pitch, and it needs no theory attached: **your scorer's tests verify the
arithmetic and never ask whether the score separates the classes.** Guardrail and
eval vendors ship on exactly that gap. It happened twice in this repository alone —
the second occurrence is recorded in
[`TRUTH_PRESSURE/ARTICLE_THE_LENS_SCORED_ZERO_2026-08-03.md`](../TRUTH_PRESSURE/ARTICLE_THE_LENS_SCORED_ZERO_2026-08-03.md).

`--gate` already exits non-zero below AUC 0.80 / accuracy 0.75. Adding a lens is one
adapter function.

### First commit

A GitHub Action wrapper: point it at a scorer and a labelled CSV, get a pass/fail
plus separation, accuracy, AUC, and a per-category breakdown. AUC and accuracy
reported side by side, because a lens that ranks correctly but thresholds badly is
cheap to fix and one that cannot rank is not.

### How we would know it worked

It fails in someone else's repository and they file the issue rather than deleting
the action.

## Bridge 4 — The failure is the paper

This is the one nobody has named as an output, and it may be the highest-value item
on the page.

On 2026-08-07 this project produced a clean, documented instance of something the
evaluation literature currently lacks a good citation for:

> A construct set was defined from theory, illustrated with examples written to fit,
> and validated against those examples at **ROC-AUC 0.940** on a held-out split.
> The same constructs scored **at chance** on two externally authored datasets.
> Internal validation was rigorous, held-out, and preregistered — and could not have
> detected the gap.

The census makes it sharp: **67 of 67** evidence paths pointed inside the repository;
zero pointed out. Not one of 67 published falsification conditions was *"check it
against data we did not write."*

Then the loop was inverted, and the repair is as informative as the failure: cues
derived *from* external labels reached 60.6% of ceiling and revealed **three of six
empirically supported harm families with no counterpart anywhere in the framework —
including the strongest one.** Theory-first construction did not merely mis-weight
what it had. It could not see a third of the space.

### Why this is publishable

Negative results about evaluation methodology are wanted, and this one has what such
papers usually lack: a preregistered internal result, an external contradiction, a
documented repair, a transfer test, an independent-publisher bound, and every number
reproducible by one command against SHA256-pinned data. The author is also the person
whose framework it falsifies, which removes the usual suspicion about adversarial
replication.

**Venues:** the evaluation and measurement tracks — NeurIPS Datasets & Benchmarks,
FAccT, or the *AI and Ethics* pipeline entry already open. A short workshop paper is
the realistic first target, not *Nature MI*.

**Honest caveat:** n=1 case study of one framework. The finding is a demonstration
that the failure mode is real and detectable, not an estimate of how common it is.

### First commit

Draft the abstract and method section from the four existing records. The experiments
are already run — this is writing, and the corpus already noticed that
([`README.md`](README.md) item 7 names scope restatement as *"the highest-value
remaining work, and it is writing, not code"*).

## What I would do first, and why

**Bridge 1.** It is the only asset that clears every filter without qualification:
it runs, it has a held-out split, its guarantee is exact rather than statistical, and
it does not touch the lens that was measured at chance. It survived 2026-08-07
completely unchanged, which nothing else here can say.

**Bridge 4 second**, because it costs no new experiment and it converts the worst day
in this project's record into its most citable contribution.

Bridges 2 and 3 are real but narrower, and both are better pitched *after* 4 exists
to cite.

### What I would not do

Not another cue family written by hand. Not a sixth preregistration — six exist in
`31_EMPIRICAL/` and **none has been executed**, and preregistration is real
methodological work that is not a result. Not a new framework document.

The structural fault named on 2026-08-07 was constructs defined from theory,
illustrated with examples written to fit, and validated against those examples. Every
item above is chosen because it either avoids that loop entirely (1, 3) or inverts it
(2, 4).
