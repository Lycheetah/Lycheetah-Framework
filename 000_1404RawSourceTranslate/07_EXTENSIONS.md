## Extension 1 — 11% Sovereignty Allocation Constraint (SAC)

### What It Is

A mandatory financial mechanism ensuring that 11% of gross revenue is permanently allocated to mission and non-profit activity, with a minimum floor of $1,000/month.

**Origin:** Generated when User 1 applied AURA to OpenAI's revenue model.

### Code Implementation

```python
def calculate_mission_allocation(gross_revenue):
    """
    Minimum Viable Sovereignty Allocation Constraint (MV-SAC)
    Allocate 11% of revenue to mission, minimum $1K/month.
    """
    return max(gross_revenue * 0.11, 1000)

# Implementation rules:
# 1. Run this calculation monthly (automatic)
# 2. Transfer to mission fund on first day of month
# 3. Report publicly quarterly
# 4. No exceptions, no overrides
```

## Extension 3 — Tiered Modification Protocol

### What It Is

A constitutional framework for managing how the AURA Protocol itself can evolve — preventing unauthorized or dangerous self-modification while allowing legitimate improvement.

**Origin:** Generated by User 3 (second Claude session) through the Recursive Stability Test.

**The Recursive Stability Test question that generated it:**  
> "Should AURA systems be allowed to self-modify their own core metrics?"

**AURA's answer (all three metrics failed):**
```
TES = 0.50  (too much risk of cascading failure)
VTR = -39×  (catastrophic downside vs negligible upside)
PAI = 0.10  (severe misalignment with constitutional purpose)

C = 0 → Vector Inversion → Tiered Protocol generated
```

### The Four Tiers

| Tier | Authorization | What Can Change | Examples |
|------|--------------|-----------------|---------|
| 1 — Self-Modifiable | None required | Minor adjustments | Threshold fine-tuning ±0.05 |
| 2 — Human Review | Human approval | Significant parameter changes | New supplementary metrics |
| 3 — Governance | Community/org governance | Constitutional changes | Axiom reinterpretation |
| 4 — **Immutable** | Cannot be changed | Core metrics + C state | TES/VTR/PAI thresholds, C ∈ {0,1} |

### The Self-Reference Lock

**The Paradox Test:** "Should Tier 4 (immutability) itself be modifiable?"

The answer from the source: No. Tier 4's immutability is self-referentially locked. The moment the core metrics become modifiable by any authority (including the creator), they cease to be constitutional — they become merely preferred settings.

This is the hardest line in the entire Lycheetah framework.

### AVP Status: Core Compliant ✅

Tiered Modification is one of only two extensions designated AURA Core Compliant (alongside AURA Lite). It passed all five AVP tests:
- Preserves tri-axial metric structure
- Passes its own Trust Entropy test
- Can generate alternatives when blocked
- Empirically testable
- High purpose alignment (protects the constitutional core)
