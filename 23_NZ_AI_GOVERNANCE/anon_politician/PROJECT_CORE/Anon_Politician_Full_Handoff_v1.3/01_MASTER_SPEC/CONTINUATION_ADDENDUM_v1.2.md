# Continuation Addendum v1.2 — From Policy Lab to Measurable Evaluation

**Date:** 16 October 2026 (Pacific/Auckland)

This addendum records the latest direction; the original master specification and transcript remain preserved as historical source material.

## Project evolution

Anon Politician is being developed as an AI-assisted governance workflow rather than an AI decision-maker. It aims to connect recurring citizen feedback, policy evidence, opposing-perspective critique, forecasting/scenario design, CASCADE dependency memory, transparent human decisions, and follow-up against real outcomes.

The proposed monthly public-input mechanism would allow politicians to ask people for views on policy questions and show how those views were considered. Public participation must be clearly distinguished from population-representative inference. Policy origin must not decide whether an idea is considered, but value disagreements and genuine trade-offs must remain visible.

## What was added in v0.2

Policy Lab v0.1 already offered an offline-first workflow UI for a current New Zealand development-levies policy case. v0.2 adds an evaluation harness to test whether the structured process offers value beyond simpler methods.

Three arms are specified: ordinary analysis, an evidence-ledger workflow, and the full Anon Politician process. The package includes matched prompts, frozen-source instructions, blind candidate assignment, a separate private mapping key, an offline human-review tool, a reviewer manual, critical issue flags, and dimension-profile aggregation without a composite winner score.

## Why the first case matters

MCERT's official development-levies page summarises 56 submissions to its 2025–26 consultation and reports different patterns in council and developer views. This is useful as a source-grounded consultation example, but not as representative national public opinion. The system should preserve what the consultation establishes without making broader claims about the public.

The Treasury's Living Standards Framework and CBAx are existing baselines. The project should test whether its integration of recurring public signals, symmetric adversarial review, dependency memory, traceable disposition, and later outcome comparisons improves the decision-support process.

## Status and next milestone

The v0.2 code tests pass: 16 unit tests, script compilation, static HTML checks, JavaScript syntax checks, and a synthetic end-to-end evaluation-pipeline check. The evaluator has not been tested end to end in a human browser. No actual candidate analysis has been generated or rated. Therefore no improvement in policy analysis is established.

The next milestone is to run the preregistered comparison on a frozen source packet, use blind independent reviewers, and publish the dimensions, critical errors, limitations, runtime and cost. Repeat with other cases before generalising.

## Non-negotiable principles

- AI assists; accountable humans decide.
- Do not invent evidence or numerical forecasts.
- Preserve source provenance, unknowns, contradictions and dissent.
- Do not claim a voluntary survey represents the public without method.
- Do not automatically rank political options or parties.
- Treat every founder-generated construct as a hypothesis until tested.
